# 學習筆記

這份筆記用白話說明 ProjectLite 每個部分在做什麼，以及為什麼這樣設計。不需要會寫程式也能看懂。

## 1. 這個網頁是怎麼組成的

一個網頁由三種檔案組成：

| 檔案 | 角色 | 比喻 |
|---|---|---|
| HTML（`index.html`） | 網頁上有哪些東西 | 建築的結構體 |
| CSS（`style.css`） | 東西長什麼樣子 | 裝修 |
| JavaScript / TypeScript（`.ts`） | 東西怎麼動 | 機電設備 |

**TypeScript** 是加上「型別檢查」的 JavaScript。例如規定「工期一定是數字」，萬一程式哪裡把文字塞進工期，還沒執行就會被抓出來。瀏覽器不認識 TypeScript，所以要先「打包」成 JavaScript。

**Vite** 就是負責打包的工具。`npm run dev` 讓你邊改邊看，`npm run build` 產出正式上線的檔案。

## 2. 為什麼要分成「資料」和「畫面」兩層

朋友那份是一個 4,000 行的檔案，資料、計算、畫面全混在一起。改一個按鈕可能不小心弄壞排程計算。

ProjectLite 分成兩層：

- **`model/` 資料層**：只管資料和計算。完全不知道畫面長什麼樣。
- **`ui/` 畫面層**：只管顯示和操作。要改資料一律請資料層處理。

好處是可以單獨測試計算對不對，也可以整個換掉畫面而不動到計算。就像結構計算書和室內設計圖分開做。

## 3. CPM 排程引擎（`schedule.ts`）

CPM 是 Critical Path Method，關鍵路徑法。

### 輸入

每個任務的工期，以及「要等誰」的前置關係。

### 第一趟：順推

從第一個任務開始往後算，每個任務**最早**何時能開始、何時能完成。

> 啟動會議 2 天（第 0～1 天）→ 需求確認 3 天，最早第 2 天開始、第 4 天完成。

有多個前置任務時，取最晚完成的那一個，因為要等大家都好了才能開始。

### 第二趟：逆推

從完工日往回推，每個任務**最晚**何時必須完成，才不會拖到完工日。

### 浮時與關鍵路徑

**浮時** = 最晚完成 − 最早完成，代表這個任務可以延誤幾天而不影響完工。

浮時為 0 的任務串起來就是**關鍵路徑**。它們任何一個晚一天，整個專案就晚一天。這就是工地最需要盯的項目。

### 四種前置關係

| 類型 | 意思 | 工地例子 |
|---|---|---|
| FS 完成→開始 | 前項做完，這項才開始 | 鋼筋綁完才能澆置混凝土 |
| SS 開始→開始 | 前項開始後，這項就能開始 | 建築設計開始 5 天後，機電設計可以同步開始（SS+5） |
| FF 完成→完成 | 前項完成後，這項才能完成 | 結構完成後，監造報告才能結案 |
| SF 開始→完成 | 前項開始後，這項才能結束 | 新系統上線後，舊系統才能停用。很少用 |

**Lag** 是關係上的延後天數。混凝土澆置後要養護 7 天才能拆模，就是 FS+7。負數叫 Lead，代表可以提前重疊。

### 循環相依

如果 A 等 B、B 又等 A，就永遠排不出來。新增前置關係時程式會先檢查，擋下會造成循環的設定。

## 4. 工作日曆（`calendar.ts`）

排程引擎只用「第幾個工作天」計算，例如第 0 天、第 1 天。工作日曆負責把它換成真正的日期，跳過週末、國定假日，並把補班日算進來。

這樣分工的好處是：要改成週休一日，只要換日曆，排程邏輯完全不用動。

朋友那份用日曆天計算，週末和假日也算進工期。這對工地來說不準確，因為假日通常不施工。

## 5. 資料日期與進度

**資料日期**是「進度回報到哪一天」。P6 的核心概念。

- 已完成的任務：用實際開始與實際完成日。
- 進行中的任務：剩下的工作從資料日期往後排。
- 還沒開始的任務：不會排在資料日期之前，因為過去的日子已經過了。

所以每次更新進度後把資料日期往前推，排程就會反映真實狀況，延誤會自動傳遞到後面的任務。

## 6. 基準線

**基準線**是某個時間點排程的快照，通常在計畫核定時存一次。

之後每次更新進度，甘特圖每條任務下方會有一條灰色細條代表原訂時間，統計列會顯示整個專案落後或超前幾個工作天。

## 7. 資料倉庫與復原（`store.ts`）

畫面上的每個操作（新增、刪除、縮排、改工期）都不直接改資料，而是呼叫資料倉庫的「動作」。

每個動作執行前，資料倉庫會先把整份專案拍一張快照放進「復原堆疊」。按 Ctrl+Z 就拿出上一張快照。最多保留 100 步。

動作執行後，資料倉庫會：重新計算排程 → 存到瀏覽器 → 通知畫面重畫。所以畫面永遠和資料一致。

## 8. 資料存在哪裡

存在瀏覽器的 **localStorage**，是每個網站在你電腦上的一個小儲存空間。

- 優點：不用帳號、不用伺服器、不用錢，資料不會外流。
- 缺點：只存在這台電腦的這個瀏覽器。清除瀏覽資料就沒了。

所以要定期「匯出備份檔」。備份檔是 `.json` 純文字格式，用記事本就能打開看。

朋友那份把 Google Sheet 的存取金鑰寫在網頁原始碼裡，任何人都能看到並修改他的試算表。ProjectLite 不連任何外部服務，沒有這個風險。

## 9. 自動測試（`tests/`）

測試是一段段「給定輸入，檢查輸出對不對」的程式。例如：

> 專案 9/7（週一）開始、週休二日，工期 5 天的任務接一個 FS 任務，後者應該在 9/14（下週一）開始。

目前有 35 個測試，涵蓋四種關係、Lag、里程碑、假日、資料日期、基準線、循環相依、復原重做。執行 `npm test` 會全部跑一次，幾秒鐘就知道有沒有改壞東西。

每次推送到 GitHub，系統也會自動跑測試，沒通過就不會發佈。

## 10. Git 與 GitHub

- **Git** 是版本控制。每次「提交（commit）」就是存一個版本，可以隨時回到任何一個版本。
- **GitHub** 是放 Git 專案的網站，也能免費架網頁（GitHub Pages）。
- **GitHub Actions** 是 GitHub 上的自動化流程。這個專案設定成：推送程式碼 → 自動測試 → 打包 → 發佈網頁。
